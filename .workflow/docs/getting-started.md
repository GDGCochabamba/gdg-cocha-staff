# Empezar una app sin encargarse de la operación técnica

## Lo que hace el responsable del negocio

Abrir una conversación dedicada al proyecto y dar la ruta del kit, una idea,
a quién ayuda y qué resultado busca. Si conoce presupuesto, plazo o restricciones,
indicarlos. No tiene que ejecutar el generador ni configurar GitHub.

Puede usar el encargo inicial `templates/new-project-request.md` del proyecto o del kit. Si todavía
no tiene toda la información, se registra como hipótesis y se propone una primera
entrega. No inventar un modelo de negocio validado para llenar una plantilla.

## Lo que hace el coordinador

1. Leer el modelo general y el perfil aplicable. No asumir que un chat nuevo
   recuerda la conversación de otro producto.
2. Crear una instancia documental en una carpeta nueva. Si ya existe el proyecto,
   comparar e incorporar el método sin sobrescribir su contexto.
3. Resumir problema, usuario, objetivo, hechos, hipótesis y decisiones de negocio
   que realmente falten. Proponer un alcance inicial razonado.
4. Investigar reutilización, decidir arquitectura dentro del mandato y preparar
   una primera entrega vertical verificable.
5. Conectar o crear el repositorio de GitHub dentro de la autorización del encargo;
   confirmar acceso y visibilidad adecuados antes de compartir material. Preparar
   Issues y PRs; no anunciar recursos que aún no existen.
6. Elegir herramientas y modelos según dificultad y cuota; lanzar trabajo solo
   cuando esté solicitado o permitido en la sesión. Verificar y demostrar el resultado.
7. Registrar continuidad para poder retomar desde documentos/Issues, sin volver a
   pedir toda la idea ni depender de memoria entre conversaciones.

El responsable revisa la experiencia de producto y decide si resuelve su necesidad.
La operación técnica y del tablero corresponde al coordinador/agentes.

## Plazos

«Una o dos noches» puede ser un objetivo de tiempo para una primera entrega acotada;
no constituye una estimación medida por tener una plantilla y agentes. Antes de
comprometer fecha se define lo entregable, se comprueba la base técnica y se mide
un flujo representativo. Diferenciar demo, MVP para piloto y producto operable.

La velocidad de escritura no sustituye validación con usuarios, corrección de datos,
permisos, funcionamiento en dispositivos y evidencia del flujo completo. No se
impone todo el catálogo histórico como primera entrega para luego prometer un plazo.

## Continuidad

Ver [trabajo prolongado](long-running-work.md). Guardar un método no crea una
sesión persistente ni una automatización. El coordinador puede avanzar sin pedir
confirmación por cada paso autorizado; una ejecución autónoma necesita objetivo,
entorno activo, presupuesto, acceso y condiciones de parada concretas.
